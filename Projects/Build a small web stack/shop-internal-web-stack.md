# Internal Web Stack: `shop.internal`

A small internal web stack built on Ubuntu/Linux using **dnsmasq**, two
Python HTTP backends, **NGINX** load balancing, and trusted HTTPS with a
self-signed certificate.

## Architecture

``` text
                         Client
                           |
                 Resolve shop.internal
                           |
                    /etc/resolv.conf
                    nameserver 127.0.0.1
                           |
                      dnsmasq :53
                 shop.internal -> 127.0.0.1
                           |
                  +--------+--------+
                  |                 |
             HTTP :80          HTTPS :443
                  |          TLS certificate
                  |          CN/SAN shop.internal
                  +--------+--------+
                           |
                    NGINX reverse proxy
                    upstream shop_backends
                      (round-robin)
                       /          \
                      /            \
             Python backend 1   Python backend 2
                :8001               :8002
              backend-1           backend-2
```

## Components

  Layer           Component                       Configuration
  --------------- ------------------------------- -----------------------------------------
  DNS             dnsmasq                         `shop.internal` resolves to `127.0.0.1`
  Backend 1       Python `http.server`            `127.0.0.1:8001`
  Backend 2       Python `http.server`            `127.0.0.1:8002`
  Load balancer   NGINX                           HTTP `:80`, HTTPS `:443`
  TLS             Self-signed X.509 certificate   CN and SAN: `shop.internal`
  Trust           OS CA trust store               `/usr/local/share/ca-certificates/`

## 1. Install packages

Run as root (or prefix commands with `sudo`):

``` bash
apt-get update
apt-get install -y dnsmasq nginx openssl curl dnsutils
```

## 2. Configure DNS with dnsmasq

Create a local DNS record:

``` bash
mkdir -p /etc/dnsmasq.d
echo "address=/shop.internal/127.0.0.1" > /etc/dnsmasq.d/shop.conf
```

### Resolve the port 53 conflict, if present

On some Ubuntu systems, `systemd-resolved` already listens on port 53.
Check:

``` bash
ss -lntup | grep ':53'
```

If the output confirms that `systemd-resolved` owns the conflicting
listener and this lab is intended to use dnsmasq as its local resolver,
stop it:

``` bash
systemctl disable --now systemd-resolved
```

Set the machine's resolver to dnsmasq:

``` bash
rm -f /etc/resolv.conf
echo "nameserver 127.0.0.1" > /etc/resolv.conf
```

Start dnsmasq:

``` bash
dnsmasq --test
systemctl enable dnsmasq
systemctl restart dnsmasq
systemctl status dnsmasq --no-pager
```

Verify the DNS answer and the system resolver:

``` bash
dig shop.internal @127.0.0.1
cat /etc/resolv.conf
getent hosts shop.internal
```

Expected DNS answer:

``` text
shop.internal.    0    IN    A    127.0.0.1
```

> **Note:** In a managed or production system, `/etc/resolv.conf` may be
> regenerated by NetworkManager, systemd-resolved, or another network
> manager. Configure the appropriate resolver manager instead of relying
> on a manually written file. Disabling `systemd-resolved` is
> appropriate only when intended for the lab.

## 3. Create and start two Python backends

Create separate document roots and index pages:

``` bash
mkdir -p /var/www/backend1 /var/www/backend2
echo "backend-1" > /var/www/backend1/index.html
echo "backend-2" > /var/www/backend2/index.html
```

Start each server in the background:

``` bash
cd /var/www/backend1
nohup python3 -m http.server 8001 --bind 127.0.0.1 \
  >/tmp/backend1.log 2>&1 &

cd /var/www/backend2
nohup python3 -m http.server 8002 --bind 127.0.0.1 \
  >/tmp/backend2.log 2>&1 &
```

Verify both backends:

``` bash
curl http://127.0.0.1:8001/
curl http://127.0.0.1:8002/
```

Expected output:

``` text
backend-1
backend-2
```

These `nohup` processes are suitable for a lab session. For a persistent
deployment, create dedicated systemd service units for the backends.

## 4. Configure NGINX load balancing

Create `/etc/nginx/sites-available/shop`:

``` nginx
upstream shop_backends {
    server 127.0.0.1:8001;
    server 127.0.0.1:8002;
}

server {
    listen 80;
    server_name shop.internal;

    location / {
        proxy_pass http://shop_backends;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

Enable the site and remove the default site if it is enabled:

``` bash
ln -sf /etc/nginx/sites-available/shop /etc/nginx/sites-enabled/shop
rm -f /etc/nginx/sites-enabled/default
nginx -t
systemctl enable nginx
systemctl restart nginx
```

Test repeated requests:

``` bash
for i in {1..6}; do curl -s http://shop.internal/; done
```

Both `backend-1` and `backend-2` should appear. NGINX uses round-robin
by default; the observed sequence may not look perfectly alternating in
every test.

## 5. Generate a certificate for HTTPS

Create a directory and generate a self-signed certificate with both the
required common name and Subject Alternative Name:

``` bash
mkdir -p /etc/nginx/ssl

openssl req -x509 -nodes -days 365 \
  -newkey rsa:2048 \
  -keyout /etc/nginx/ssl/shop.key \
  -out /etc/nginx/ssl/shop.crt \
  -subj "/CN=shop.internal" \
  -addext "subjectAltName=DNS:shop.internal"
```

The private key should be readable only by root:

``` bash
chmod 600 /etc/nginx/ssl/shop.key
```

Inspect the certificate:

``` bash
openssl x509 -in /etc/nginx/ssl/shop.crt -noout -subject -issuer -ext subjectAltName
```

## 6. Add the certificate to the system trust store

On Ubuntu/Debian:

``` bash
cp /etc/nginx/ssl/shop.crt /usr/local/share/ca-certificates/shop.crt
update-ca-certificates
```

This makes the certificate trusted by clients that use the system CA
bundle. Trust stores are machine-specific; other clients or machines
need their own trust configuration.

> **Security note:** A self-signed certificate is suitable for this
> isolated lab. For production, use a certificate issued by your
> organization's trusted internal CA or a publicly trusted CA. Protect
> and manage the private key carefully.

## 7. Enable HTTPS in NGINX

Replace `/etc/nginx/sites-available/shop` with:

``` nginx
upstream shop_backends {
    server 127.0.0.1:8001;
    server 127.0.0.1:8002;
}

server {
    listen 80;
    server_name shop.internal;

    location / {
        proxy_pass http://shop_backends;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

server {
    listen 443 ssl;
    server_name shop.internal;

    ssl_certificate /etc/nginx/ssl/shop.crt;
    ssl_certificate_key /etc/nginx/ssl/shop.key;

    location / {
        proxy_pass http://shop_backends;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

Validate and reload NGINX:

``` bash
nginx -t
systemctl restart nginx
```

## 8. End-to-end verification

Run the following checks:

``` bash
# DNS record
dig shop.internal @127.0.0.1

# System resolver
getent hosts shop.internal

# Backend responses
curl http://127.0.0.1:8001/
curl http://127.0.0.1:8002/

# Listening ports
ss -lntp | grep -E ':(53|80|443|8001|8002)\b'

# HTTP through NGINX
for i in {1..6}; do curl -s http://shop.internal/; done

# HTTPS through NGINX (no -k)
curl https://shop.internal/

# Repeated HTTPS requests to observe both backends
for i in {1..6}; do curl -s https://shop.internal/; done

# Certificate details
openssl s_client -connect shop.internal:443 -servername shop.internal </dev/null
```

The final HTTPS `curl` command must succeed **without** `-k` and should
return content from the backend pool.

## Troubleshooting

### dnsmasq fails with `Address already in use`

Identify the process using port 53:

``` bash
ss -lntup | grep ':53'
```

If it is `systemd-resolved` and the lab is intended to use dnsmasq
directly, stop it as described in the DNS section. Then restart dnsmasq.

### NGINX fails to start

Check configuration syntax and logs:

``` bash
nginx -t
journalctl -u nginx --no-pager -n 50
```

### A backend does not respond

Check listeners and backend logs:

``` bash
ss -lntp | grep -E ':(8001|8002)\b'
cat /tmp/backend1.log
cat /tmp/backend2.log
```

### HTTPS reports an untrusted certificate

Confirm the certificate was installed and the trust bundle was updated:

``` bash
ls -l /usr/local/share/ca-certificates/shop.crt
update-ca-certificates
curl -v https://shop.internal/
```

Also confirm that the certificate SAN contains `DNS:shop.internal` and
that the client uses the system CA store.
